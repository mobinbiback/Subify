# Subify Lite — راهنمای اندروید و آیفون

این پوشه نسخهٔ «فقط ترجمهٔ زیرنویس» Subify است — همون موتور ترجمه، بدون دوبلهٔ صوتی — چون Firefox (دسکتاپ/اندروید) و Safari (iOS) اصلاً `chrome.tabCapture`/`chrome.offscreen` رو ندارن. جزئیات فنی کامل در `CHANGELOG.md` و `PRIVACY.md`.

## ۱. تست روی Firefox دسکتاپ (قبل از هر کار دیگه)

1. `about:debugging#/runtime/this-firefox` رو باز کن
2. «Load Temporary Add-on…» بزن و فایل `manifest.json` همین پوشه رو انتخاب کن
3. یه ویدیوی یوتیوب/ویمیو/آپارات/Coursera باز کن و از Popup افزونه کلید API و ترجمه رو تست کن

این نصب موقتیه و با بستن Firefox پاک می‌شه — فقط برای مطمئن‌شدن از سالم‌بودن کد قبل از قدم بعدیه.

## ۲. تست روی Firefox اندروید (قبل از انتشار)

Firefox اندروید به‌صورت پیش‌فرض فقط یه لیست محدود از افزونه‌های AMO رو نشون می‌ده، ولی می‌شه یه افزونهٔ محلی/غیرمنتشرشده رو هم تست کرد:

1. **Firefox Nightly برای اندروید** نصب کن (نسخهٔ عادی این قابلیت رو نداره)
2. گوشی رو با کابل USB به کامپیوتر وصل کن و USB debugging رو در تنظیمات اندروید فعال کن
3. در کامپیوتر: `about:debugging` در Firefox دسکتاپ رو باز کن، گوشی باید زیر «Enable USB Debugging» ظاهر بشه — روش کلیک کن و «Load Temporary Add-on» رو مثل حالت دسکتاپ انجام بده، این بار پکیج روی گوشی نصب/اجرا می‌شه

اگه این تست‌ها رو رد کرد، آماده‌ای برای انتشار رسمی.

## ۳. انتشار روی addons.mozilla.org (AMO) — تنها راه نصب عادی برای کاربرهای اندروید

1. حساب Mozilla Add-on Developer بساز: https://addons.mozilla.org/developers/
2. این پوشه رو zip کن (بدون خود فایل zip قبلی، فقط محتویات این پوشه) و در «Submit a New Add-on» آپلود کن
3. موقع Submit، گزینهٔ سازگاری با Android رو فعال کن — چون `browser_specific_settings.gecko_android` از قبل در `manifest.json` تنظیم شده
4. منتظر ریویوی Mozilla بمون (معمولاً چند روز تا چند هفته)؛ اگه ریجکت شد، دلیلش رو می‌گه و می‌شه دوباره فرستاد

نکته: `browser_specific_settings.gecko.id` توی manifest یه مقدار پیشنهادیه (`subify-lite@mobinbibak.dev`). همینو نگه دار یا با شناسهٔ دلخواه خودت عوضش کن — فقط بعد از اولین Submit دیگه دستش نزن، چون AMO این id رو برای شناسایی نسخه‌های بعدی استفاده می‌کنه.

بعد از تأیید، کاربرهای اندروید از همون صفحهٔ AMO یا مستقیم از منوی افزونه‌های Firefox اندروید نصبش می‌کنن — نیازی به هیچ‌کاری از سمت تو نیست.

## ۴. آیفون — این یکی مسیر کاملاً جدایی می‌خواد

هیچ مرورگری روی iOS نمی‌تونه یه افزونهٔ Chrome/Firefox معمولی رو مستقیم نصب کنه (اپل همهٔ مرورگرها رو مجبور به استفاده از WebKit خودش می‌کنه). تنها راه، بازسازی به‌عنوان یه **Safari Web Extension** و انتشار به شکل اپ در App Store است:

**پیش‌نیازها (چیزهایی که من از اینجا ندارم و نمی‌تونم فراهم کنم):**
- یه Mac با Xcode نصب‌شده
- حساب Apple Developer Program (۹۹ دلار در سال)

**مراحل کلی روی Mac:**
1. Xcode رو نصب کن، بعد در Terminal بزن:
   ```
   xcrun safari-web-extension-converter /path/to/این-پوشه
   ```
   این ابزار یه پروژهٔ Xcode می‌سازه که همین کد HTML/CSS/JS رو به‌عنوان یه Safari Web Extension بسته‌بندی می‌کنه.
2. پروژه رو در Xcode باز کن، آیکون‌ها و اطلاعات اپ رو تنظیم کن
3. با حساب Apple Developer، اپ رو Sign و از طریق TestFlight (برای تست محدود) یا App Store (برای انتشار عمومی) بفرست

**نکات مهم:**
- Safari هم `tabCapture` نداره، پس این محدودیت اونجا هم صادقه — این پکیج Lite دقیقاً برای همین ساخته شده.
- بعضی جزئیات Manifest V3 (مثل `service_worker`) ممکنه نیاز به تنظیم جزئی برای Safari داشته باشه؛ ابزار تبدیل اپل معمولاً خودش هشدار می‌ده کجا نیاز به اصلاح دستیه.
- این مسیر رو من نمی‌تونم برات انجام بدم (نه Mac دارم، نه Xcode، نه حساب Apple Developer) — ولی کد پایه (همین پوشه) دقیقاً چیزیه که `safari-web-extension-converter` بهش نیاز داره.

## خلاصه

| پلتفرم | چیکار کنیم | چقدر کار می‌بره |
|---|---|---|
| Firefox دسکتاپ | نصب موقت، تست کن | چند دقیقه |
| Firefox اندروید | تست از راه دور با Nightly + USB، بعد انتشار در AMO | چند ساعت + زمان ریویوی Mozilla |
| آیفون (Safari) | بازسازی با Xcode، انتشار در App Store | نیاز به Mac/Xcode/Apple Developer — پروژهٔ جدا |
