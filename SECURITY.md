# Security Policy

## Supported Versions

Security updates are currently provided for the latest actively maintained version of Subify.

Older versions may not receive security fixes.

## Reporting a Vulnerability

If you believe you have found a security vulnerability in Subify, please do not disclose it publicly through GitHub Issues, Pull Requests, Discussions, or other public channels.

Instead, please report the vulnerability privately through GitHub:

https://github.com/mobinbiback/Subify/security/advisories/new

If private security advisories are not available for your situation, you may contact the project maintainer privately through:

https://github.com/mobinbiback

## What to Include

Please include as much of the following information as possible:

- A clear description of the vulnerability
- The affected component or feature
- The affected Subify version or commit
- Steps to reproduce the issue
- Proof of concept, if available
- The potential security impact
- Any suggested mitigation or fix

Please do not include passwords, API keys, access tokens, personal information, or other sensitive credentials in your report.

## Responsible Disclosure

Please allow reasonable time for the maintainer to investigate the report and, when appropriate, prepare and release a security fix before publicly disclosing the vulnerability.

Security reports will be handled with reasonable confidentiality during the investigation.

## Scope

This policy applies to security vulnerabilities affecting the Subify project and its officially distributed extension code.

Issues that are not security vulnerabilities should be reported through the project's GitHub Issues.

## Security Updates

When appropriate, security fixes may be documented through:

- GitHub Security Advisories
- Release notes
- GitHub repository updates

The level of public disclosure will depend on the nature and impact of the vulnerability.
